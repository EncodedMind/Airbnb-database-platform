Μέρος Α: Δημιουργία Διαγράμματος Οντοτήτων-Συσχετίσεων

Η διαδικασία που ακολουθήσαμε για τη σχεδίαση του σχήματος μπορεί να χωριστεί στα ακόλουθα βήματα:

1. Προσδιορισμός Συνόλων Οντοτήτων

Αρχικά, διαβάζοντας την εκφώνηση, αναζητήσαμε αντικείμενα του κόσμου που περιγράφεται με κοινά χαρακητριστικά, τα οποία ομαδοποιήσαμε στα ακόλουθα ανεξάρτητα σύνολα οντοτήτων: 

1. Χρήστες
	-	Σύνολα οντοτήτων: User (Χρήστης), Host (Οικοδεσπότης), Guest (Φιλοξενούμενος), Photo (Φωτογραφία)
	-	Ο χρήστης είναι μία από τις κύριες οντότητες του σχήματος η οποία συνδέεται μέσω της 1-1 συσχέτισης "is" με τον/τους ειδκότερο/ους ρόλο/ους του (Φιλοξενούμενος ή/και Οικοδεσπότης). Ακόμη, μέσω της συσχέτισης User has Photo, έχουμε πρόσβαση στη φωτογραφία προφίλ κάθε χρήστη.

2. Διαχείριση Ακινήτων
	-	Σύνολα οντοτήτων: Property (Ακίνητο), Facility (Παροχή), Rule (Κανόνας), Cancelation Property (Πολιτική Ακύρωσης), Friend Policy (Πολιτική Φίλων), Photo (Φωτογραφία)
	-	Τα ακίνητα αποτελούν κεντρική οντότητα του συστήματος και περιλαμβάνουν τις πληροφορίες του χώρου που προσφέρεται προς φιλοξενία. Κάθε ακίνητο:
		-	έχει φωτογραφίες, οι οποίες αποθηκεύονται μέσω ενός συνδέσμου (link),
		-	συνδέεται με πολλές παροχές (όπως WiFi, πάρκινγκ),
		-	ακολουθεί συγκεκριμένους κανόνες που θέτει ο οικοδεσπότης (π.χ. ώρες check-in, κατοικίδια).
		-	έχει πιθανόν πολιτική ακύρωσης και φίλων, οι όροι των οποίων περιγράφονται στα πεδία των αντίστοιχων οντοτήτων.
	
	Παρατήρηση: Για την υλοποίηση των κανόνων και των παροχών κάθε καταλύματος σκεφτήκαμε δύο προσεγγίσεις:
	1. Να εισάγουμε τις γενικές οντότητες "Rules" και "Facilities", οι οποίες θα έχουν ένα boolean πεδίο για κάθε πιθανό κανόνα/παροχή. Η τιμή του πεδίου εκφράζει αν ο συγκεκριμένος κανόνας ή παροχή εφαρμόζεται/είναι διαθέσιμη στο κατάλυμα.
	2. Να εισάγουμε τις οντότητες "Rule" και "Facility", οι οποίες αποτελούνται από ένα πρωτεύον κλειδί (ruleId, facilityId) με πεδία "Τίτλος" και "Περιγραφή". Κάθε κατάλυμα συσχετίζεται όσους κανόνες εφαρμόζονται και όσες παροχές είναι διαθέσιμες σε αυτό.
   	
	Στη βάση μας ακολουθήσαμε τη 2η προσέγγιση, καθώς προσφέρει ευελιξία και δεν απαιτεί αλλαγή του σχήματος για την προσθήκη νέων κανόνων/παροχών. Ωστόσο, η στρατηγική αυτή εισάγει μία επιπλέον πολυπλοκότητα στο επίπεδο της εφαρμογής.

3. Κρατήσεις και Πληρωμές
	-	Σύνολα οντοτήτων: Booking (Κράτηση), Time Period (Χρονική Περίοδος), Payment (Πληρωμή), Discount (Έκπτωση), Reward (Ανταμοιβή)
	-	Η κράτηση ενός ακινήτου περιλαμβάνει μια σειρά από συνδεδεμένες πληροφορίες:
		-	Ημερομηνίες άφιξης και αναχώρησης,
		-	Πληρωμή της κράτησης,
		-	Εκπτώσεις, που μπορεί να εφαρμόζονται βάσει προσφορών, αριθμού φίλων ή άλλων κριτηρίων,
		-	Ανταμοιβές, που δίνονται σε χρήστες για συγκεκριμένες ενέργειες (π.χ. σύσταση φίλων).
	
	Παρατήρηση: Η προβολή και διαχείριση του διαθέσιμων ημερομηνιών κάθε καταλύματος πραγματοποιείται μέσω της συσχέτισης Property is availiable during Time Period. Ο συγχρονισμός ημερολογίου και κρατήσεων δεν εξασφαλίζεται από το σχήμα και αποτελεί ευθύνη του προγραμματιστή.

4. Επικοινωνία και Κοινωνική Αλληλεπίδραση
	-	Σύνολα οντοτήτων: Message (Μήνυμα), Friend (Φίλος), Supporter (Υποστηρικτής)
	-	Η πλατφόρμα ενθαρρύνει την αλληλεπίδραση μεταξύ των χρηστών μέσω:
		-	Μηνυμάτων που επιτρέπουν την επικοινωνία (π.χ. πριν ή μετά την κράτηση),
		-	Φιλικών σχέσεων, οι οποίες μπορούν να προσφέρουν προνόμια μέσω της Πολιτικής Φίλων (π.χ. εκπτώσεις για κρατήσεις από φίλους),
		-	Υποστηρικτών, οι οποίοι βοηθούν στην προώθηση/διαχείριση των καταλυμάτων, π.χ. ως εξωτερικοί συνεργάτες.

5. Αξιολόγηση και Αιτήματα
	-	Σύνολα οντοτήτων: Review (Αξιολόγηση), Request (Αίτημα)
	-	Το σύστημα υποστηρίζει:
		-	Αξιολογήσεις, μέσω των οποίων οι φιλοξενούμενοι βαθμολογούν ακίνητα και οι οικοδεσπότες βαθμολογούν τους φιλοξενούμενους.	
		-	Αιτήματα, που καταθέτουν οι χρήστες για τη βελτίωση των καταλυμάτων.

2. Προσδιορισμός Συσχετίσεων

Παρακάτω παρατίθεται η επεξήγηση των συσχετίσεων του σχήματος και ο πληθικός τους αριθμός, στην παρακάτω μορφή:

1ο πεδίο - Συσχέτιση - 2ο πεδίο - Πληθικός Αριθμός - Σχόλια

User - is - Guest - 1:1 - Δεν υπάρχει φιλοξενούμενος χωρίς χρήστη. Κάθε χρήστης μπορεί να αντιστοιχεί σε το πολύ έναν φιλοξενούμενο.

User - is - Host - 1:1 - Δεν υπάρχει οικοδεσπότης χωρίς χρήστη. Κάθε χρήστης μπορεί να αντιστοιχεί σε το πολύ έναν οικοδεσπότη.

User - has - Photo - 1:N - Κάθε χρήστης μπορεί να έχει το πολύ μία φωτογραφία. Μία φωτογραφία μπορεί να έχει επιλεγεί ως φωτογραφία προφίλ από πολλούς χρήστες.

Photo - shows - Property - N:1 - Ένα ακίνητο μπορεί να έχει πολλές φωτογραφίες, όμως μία φωτογραφία μπορεί να απεικονίζει το πολύ ένα ακίνητο.

Message - is sent by - User - N:1 - Ένα μήνυμα στέλνεται από ακριβώς έναν χρήστη (identifying συσχέτιση) αλλά ένας χρήστης μπορεί να στείλει πολλά μηνύματα.

Message - is received by - User - N:1 - Ένα μήνυμα λαμβάνεται από ακριβώς έναν χρήστη (identifying συσχέτιση) αλλά ένας χρήστης μπορεί να λάβει πολλά μηνύματα.

Payment - repays - Booking - N:1 - Μία πληρωμή συνδέεται με ακριβώς μία κράτηση (identifying συσχέτιση) αλλά μία κράτηση μπορεί να εξοφλείται με πολλές πληρωμές.

Payment - is made by - Guest - N:1 - Μία πληρωμή γίνεται από ακριβώς έναν φιλοξενούμενο (identifying συσχέτιση) αλλά ένας φιλοξενούμενος μπορεί να κάνει πολλές πληρωμές.

Booking - is made by - Guest - N:1 - Μία κράτηση γίνεται από ακριβώς έναν φιλοξενούμενο (identifying συσχέτιση) αλλά ένας φιλοξενούμενος μπορεί να κάνει πολλές κρατήσεις.

Request - is made by - Guest - N:1 - Ένας χρήστης μπορεί να κάνει πολλά αιτήματα, αλλά κάθε αίτημα γίνεται από ακριβώς έναν χρήστη (identifying συσχέτιση).

Rule - is applied in - Property - N:M - Ένα ακίνητο μπορεί να έχει πολλούς κανόνες και ένας κανόνας μπορεί να εφαρμόζεται σε πολλά ακίνητα.

Property - has - Friend Policy - N:1 - Ένα ακίνητο μπορεί να έχει το πολύ μία πολιτική φίλων, αλλά η ίδια πολιτική φίλων μπορεί να εφαρμόζεται σε πολλά ακίνητα.

Property - has - Cancelation Policy - N:1 - Ένα ακίνητο μπορεί να έχει το πολύ μία πολιτική ακυρώσεων, αλλά η ίδια πολιτική ακυρώσεων μπορεί να εφαρμόζεται σε πολλά ακίνητα.

Property - is owned by - Host - N:1 - Ένα ακίνητο έχει ακριβώς έναν ιδιοκτήτη (identifying συσχέτιση), αλλά ένας ιδιοκτήτης μπορεί να έχει πολλά ακίνητα.

Property - is in wish list of - User - N:M - Ένα ακίνητο μπορεί να είναι στη λίστα επιθυμιών πολλών χρηστών, ένας χρήστης μπορεί να έχει πολλά ακίνητα στη λίστα επιθυμιών του.

Property - is in favorites list of - User - N:M - Ένα ακίνητο μπορεί να είναι στη λίστα αγαπημένων πολλών χρηστών, ένας χρήστης μπορεί να έχει πολλά ακίνητα στη λίστα αγαπημένων του.

Booking - on - Property - N:1 - Ένα ακίνητο μπορεί να δέχεται πολλές κρατήσεις, μία κράτηση αφορά ακριβώς ένα ακίνητο (identifying συσχέτιση).

Supporter - manages - Property - N:M - Ένας υποστηρικτής μπορεί να υποστηρίζει πολλά ακίνητα και ένα ακίνητο μπορεί να έχει πολλούς υποστηρικτές. Ως πεδίο της συσχέτισης προστίθεται ο ρόλος του υποστηρικτή (π.χ. προώθηση/διαχείριση).

Property - has - Facility - N:M - Μία παροχή μπορεί να υπάρχει σε πολλά καταλύματα, ένα κατάλυμα μπορεί να έχει πολλές παροχές.

Discount - is offered to - Guest - N:1 - Κάθε έκπτωση είναι μοναδική, προσφέρεται σε ακριβώς έναν φιλοξενούμενο (identifying συσχέτιση), αλλά ένας φιλοξενούμενος μπορεί να δέχεται πολλές εκπτώσεις.

Discount - on - Property - N:1 - Κάθε έκπτωση είναι μοναδική, αφορά ακριβώς ένα ακίνητο (identifying συσχέτιση), αλλά ένα ακίνητο μπορεί να έχει πολλές εκπτώσεις.

Reward - is received by - User - N:1 - Κάθε ανταμοιβή είναι μοναδική, προσφέρεται σε ακριβώς έναν χρήστη (identifying συσχέτιση), αλλά ένας χρήστης μπορεί να δέχεται πολλές ανταμοιβές.

Reward - is offered by - Host - N:1 - Κάθε ανταμοιβή είναι μοναδική, δίνεται από ακριβώς έναν οικοδεσπότη (identifying συσχέτιση) αλλά ένας οικοδεσπότης μπορεί να δώσει πολλές ανταμοιβές.

Review - is made by - Guest - N:1 - Κάθε κριτική γίνεται από ακριβώς έναν φιλοξενούμενο (identifying συσχέτιση) αλλά ένας φιλοξενούμενος μπορεί να κάνει πολλές κριτικές.

Review - on - Property - N:1 - Κάθε κριτική συνδέεται με ακριβώς ένα ακίνητο (identifying συσχέτιση), αλλά ένα ακίνητο μπορεί να δέχεται πολλές κριτικές.

Review - is made by - Host - N:1 - Κάθε κριτική γίνεται από ακριβώς έναν οικοδεσπότη (identifying συσχέτιση) αλλά ένας οικοδεσπότης μπορεί να κάνει πολλές κριτικές.

Review - on - Guest - N:1 - Κάθε κριτική συνδέεται με ακριβώς έναν φιλοξενούμενο (identifying συσχέτιση), αλλά ένας φιλοξενούμενος μπορεί να δέχεται πολλές κριτικές.

Property - is available during - Time Period - N:M - Σε κάθε χρονική περίοδο μπορούν πολλά ακίνητα να είναι διαθέσιμα και ένα ακίνητο μπορεί να είναι διαθέσιμο σε πολλές ημερομηνίες.

Host - is represented by - User - N:M - Ένας οικοδεσπότης μπορεί να εκπροσωπείται από πολλούς χρήστες, ένας χρήστης μπορεί να εκπροσωπεί πολλούς οικοδεσπότες.

User - cooperates with - User - 1:N - Κάθε χρήστης μπορεί να συνεργάζεται με πολλούς άλλους χρήστες.

Reward - is given on - Property - N:1 - Μία ανταμοιβή δίνεται σε ακριβώς ένα ακίνητο (identifying συσχέτιση) αλλά ένα ακίνητο μπορεί να έχει πολλές ανταμοιβές.

Friend - is invited by - User - N:1 - Κάθε χρήστης μπορεί να προσκαλέσει πολλούς φίλους αλλά κάθε φίλος προσκαλείται από έναν χρήστη.

Friend - is invited at - Property - 1:N - Κάθε φίλος προσκαλείται σε ακριβώς ένα ακίνητο αλλά ένα ακίνητο μπορεί να δέχεται πολλούς προσκεκλημένους φίλους.

Γενικές παρατηρήσεις:

-	Θεωρούμε ότι κάθε ακίνητο έχει ακριβώς έναν κύριο οικοδεσπότη/ιδιοκτήτη. Οποιοσδήποτε άλλος συμμετέχει στη διαχείριση του ακινήτου έχει διαφορετικό ρόλο στην πλατφόρμα.

-	Η βάση καταγράφει την πρώτη φορά που κάποιος φίλος προσκαλείται σε ένα συγκεκριμένο ακίνητο. Κατά συνέπεια, κάθε φίλος προσκαλείται στο ακίνητο από ακριβώς έναν χρήστη και για αυτό η αντίστοιχη συσχέτιση έχει πληθικό αριθμό 1-Ν.

-	Σύμφωνα με την εκφώνηση, "οικοδεσπότες διαχειρίζονται τις διαθέσιμες ημερομηνίες" των καταλυμάτων τους. Ωστόσο, στο σχήμα δεν υπάρχει συσχέτιση Host manages Time Period, καθώς αυτό θα οδηγούσε σε πλεονασμό. Πράγματι, κάθε ακίνητο συνδέεται με ακριβώς έναν οικοδεσπότη σύμφωνα με την παραπάνω υπόθεση, επομένως η συσχέτιση "Property is availiable during Time Period" αρκεί για να προσδιορίσουμε τόσο το κατάλυμα όσο και τον οικοδεσπότη με τον οποίο συνδέεται μία ημερομηνία Date.

-	Το ιστορικό συναλλαγών κάθε χρήστη προσδιορίζεται από τη συσχέτιση "User makes Payment".

-	Η σύγκριση των ακινήτων με βάση τις κριτικές των χρηστών πραγματοποιείται στο επίπεδο της εφαρμογής και δεν υλοποιείται στο σχήμα.

Μέρος Β

1)	Δημιουργία νέας οντότητας: Υπάλληλος (π.χ. καθαρίστριες, σερβιτόροι, κ.τ.λ.)
Ένας υπάλληλος χαρακτηρίζεται μοναδικά από το EmployeeID του.
Συσχέτιση: Employee - works at – Property
Ο υπάλληλος μπορεί να εργαστεί σε πάνω από ένα καταλύματα.
Επιπλέον, ένα κατάλυμα μπορεί να απασχολεί πολλούς υπαλλήλους.
Άρα, ο πληθικός αριθμός της συσχέτισης είναι: N:M

2)	Δημιουργία νέας συσχέτισης: has_matching_rate_with
User - has_matching_rate_with - Property
Περιέχει ένα ποσοστό, που καταδεικνύει την πιθανότητα να αρέσει ένα κατάλυμα σε έναν χρήστη, μέσω ενός συστήματος τεχνητής νοημοσύνης.
Πληθικός αριθμός: N:M, καθώς ένας χρήστης «ταιριάζει» με πολλά καταλύματα και το αντίστροφο.

3)	Δημιουργία νέας οντότητας: Αξιοθέατα κοντά στο κατάλυμα
Ένα αξιοθέατο χαρακτηρίζεται μοναδικά από τις συντεταγμένες (τοποθεσία) του.
Συσχέτιση: Property - has - Nearby_Attractions
Ένα κατάλυμα μπορεί να έχει πάνω από ένα κοντινά αξιοθέατα και ένα αξιοθέατο μπορεί να είναι κοντά σε πολλά καταλύματα.
Άρα, ο πληθικός αριθμός της συσχέτισης είναι: N:M

4)	Δημιουργία νέου πεδίου στα καταλύματα: Οδηγίες για το check-in
Περιέχει πληροφορίες σε μορφή κειμένου για τον τρόπο που ο φιλοξενούμενος θα μπει στο κατάλυμα, π.χ. Τοποθεσία κλειδιού/ κωδικός κλειδαριάς, κ.τ.λ.

5)	Δημιουργία νέας οντότητας: Διαφήμιση
Ένα ακίνητο συνοδεύεται από διάφορες διαφημίσεις για αυτό, στην πλατφόρμα.
Μία διαφήμιση χαρακτηρίζεται μοναδικά από το AdvertisementID της.
Συσχέτιση: Property - has - Advertisement
Ένα κατάλυμα μπορεί να έχει πολλές διαφημίσεις, αλλά μία διαφήμιση αφορά μόνο ένα κατάλυμα.
Άρα, ο πληθικός αριθμός της συσχέτισης είναι: 1:N
